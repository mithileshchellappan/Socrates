# MailUI

The Mail screen (PRD #30–#35 UI, mockup 05), the sidebar's mail rows, the Message menu and the mail account settings. Workstream C of M2. Depends on StudyCore, StudyUI and LocalTranslation (Translate) only; every effect goes through `MailActions` (`\.mailActions`), which the app wires to Mail (sync, send, verify), MailIntelligence (routing, drafts, Undo) and Courses (proposals).

No automated test suite at present; verified by building and rendering.

## Public surface

```swift
public struct MailView: View { public init(scope: MailScope, selection: Binding<MailMessage.ID?>, query: String = "", now: Date? = nil) }
public struct MailScopeLabel: View { public init(scope: MailScope) }     // sidebar row label with the unread badge
public struct MailAccountSettingsView: View { public init() }           // Section content: put it in the settings Form
public struct MailCommands: Commands { public init() }                  // the Message menu
public struct MailActions { … }                                         // frozen §2.5, plus three members with defaults (below)
```

- **MailView**: list (318 pt) | reader. List rows: sender, time ("13:37" in SF Mono / "Yesterday" / `DayText`), M3.5: a tertiary `arrowshape.turn.up.left` before the flag and the time while triage says the mail asks the student something and it is not answered (`needs_reply` true, `is_answered` false; not in Sent; no chip, no copy; its context menu adds **No Reply Needed** → `setNeedsReply(id, false)`), subject with the course dot, snippet, unread dot, one extra line only for a proposal ("Move to Room 5?", a menu with Confirm / Discard) or a learning platform's "New file" mail whose file smart import filed (the lecture as a menu: Open Lecture N, Change…). Reader: subject; initials, sender, address, date; To and the route menu (courses, University, Newsletters, Personal, Other → `route`); the found block (one sparkle; In Calendar + Undo / Add to Calendar / Discard + Confirm / in calendar without Undo for an existing session / Restore after Undo); the body (sanitized HTML via `XMLParser`, else `body_text` with detected links; found rows in the order their quotes stand in the mail; found quotes underlined dotted in `Color.ai`; quoted replies collapsed); attachment chips (Quick Look, drag out through `openAttachment`); the inline reply. Drafts scope: `selection` is the **draft's** id; a reply shows under its message, a new message alone. Without an account: only Set Up Mail….
- **Reply** asks `draftReply` (the agent streams into the row); if that throws (no key, unwired, an error) the screen writes an empty threaded reply itself. **New Message** writes an empty draft (no agent). Typing while the agent writes calls `stopDrafting` once; the text is saved through `MailDraftRepository.editBody` 0.4 s after typing pauses and before Send. **Discard** stops the agent and deletes the draft row. **Send** (the one filled button; ⇧⌘D from the menu) saves, then calls `send` once; disabled while generating, sending, without a recipient or text; a failure shows its reason under the editor and Send works again.
- **Translate** (decisions: "Mail Translate", 2026-10-20 row): a `translate` toggle after Flag, shown only when the reader's `NLLanguageRecognizer` pass finds the mail's own text in another language than `Locale.preferredLanguages.first` and `LocalTranslator.canTranslate` has a model route for the pair (synchronous, no download). It runs on the device with local-translate's OPUS-MT models (package LocalTranslation; no Apple Translation, no Claude): `MailTranslationJob.run` (`@concurrent`) hands `MailTranslationInput.texts` (the subject, then each unquoted block's lines, plain text) to `LocalTranslator.shared.translations(of:from:to:)` and puts results in place as they stream back: the subject first (it stays primary), then each block once all its lines are back (`translatedBlock`, links re-detected, `MailBlock.isTranslated`, drawn `.secondary`); a block still waiting shows the original. The first use of a pair downloads its model (about 108 MB) into `Application Support/Socrates/Models/Translation`; meanwhile a thin determinate `ProgressView` runs along the reader's top edge (help "Downloading model"; no spinner, no copy). Switching messages or turning Translate off cancels the job and drops the partial result (finished sentences come back from the translator's cache). A failure turns Translate off and gives the toggle the help "Couldn’t finish". Translations stay in memory per message for the session (`MailTranslations`); the draft, the found block, quoted mail and attachments are never translated. No app wiring needed beyond the `LocalTranslation` package entry in `project.yml`.
- **Keys** (`MailCommands`, attached only while Mail is in the key window, docs/decisions.md 161): Reply ⌘R, Send ⇧⌘D (only while a composer is on screen), Archive ⌃⌘A, Flag ⇧⌘L, Mark as Read/Unread ⇧⌘U, Translate/Show Original ⌃⌘T; New Message and Get Mail have no keys (⌘N is File ▸ New Window, ⇧⌘N New Lecture Capture). Reply/Archive/Flag/Mark/Translate are disabled while text is typed (the editor or the window's search field, `\.isSearchFieldFocused`). In the list: ↑/↓, ↩ moves focus into the reader (↑/↓ scroll, Space pages, Escape returns), Delete archives. Checked against `menus.txt` of the M1 app snapshot run: no collisions.
- **MailAccountSettingsView**: name, email address, account name, password (`SecureField`; a stored password shows as dots in the prompt, never its value), servers (the student's own: a new account starts without hosts, ports 993 TLS and 587 STARTTLS, and "Servers" is open while a host is missing). Save = `verifyAccount` (logs in, sends nothing) → `secrets.setSecret(password, for: account.passwordKey)` → the row (no secret) → `accountSaved`. Test Connection verifies without saving. An empty password field uses the stored one; renaming the account moves the Keychain item. Failures (and the sync engine's `last_error` while nothing is being edited) show in red under the password. Save is filled only while there are unsaved changes.
